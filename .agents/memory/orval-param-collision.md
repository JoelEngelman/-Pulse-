---
name: Orval query-param collision fix
description: How to prevent TS2308 duplicate export errors when Orval generates param types for operations with query parameters.
---

## The Rule
Remove `schemas: { path: "generated/types", type: "typescript" }` from the `zod` output config in `lib/api-spec/orval.config.ts`. Keep `lib/api-zod/src/index.ts` as `export * from "./generated/api"` only (no `./generated/types` export).

**Why:** For any operation with query parameters, Orval generates `<OperationIdPascal>Params` in BOTH `generated/api.ts` (Zod schema) AND `generated/types/` (TypeScript interface). The barrel re-exports both with `export *`, causing TS2308: "Module already exported a member named X". The `generated/types` folder is not needed by the server; Zod schemas in `api.ts` are sufficient.

**How to apply:** Any time you add a new operation with query parameters to the OpenAPI spec (e.g., `?search=`, `?before=`, `?q=`), the collision will occur unless this fix is in place. Verify `orval.config.ts` does not have the `schemas` key in the `zod` output block.

**Critical:** `lib/api-zod/src/index.ts` is NOT regenerated by Orval's `clean: true` — it's a manually maintained barrel file. Check it after any codegen run if errors reappear.
